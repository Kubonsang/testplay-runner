# TestPlay Runner v0.12.0 — Native CoW Storage Foundation

Released 2026-08-03.

## Summary

v0.12.0 ships the cross-platform `testplay-storage-helper` as an experimental
integration primitive. The public `testplay` CLI contract is unchanged, the
storage-helper protocol remains schema 1, and the helper implementation reports
version `v2`.

| Platform | Native provider | Released helper target |
|---|---|---|
| Windows | Differencing VHDX | `windows-amd64` |
| macOS | APFS `clonefileat(2)` | `darwin-amd64`, `darwin-arm64` |
| Linux | reflink through GNU `cp --reflink=always` | `linux-amd64` |

The production default backend is unchanged. The helper is not connected to
`testplay run`, is not selected automatically, never silently falls back to a
physical copy, and is not production-ready.

## What is included

- Existing `testplay` CLI archives for Darwin amd64/arm64, Linux amd64/arm64,
  and Windows amd64.
- Separate `testplay-storage-helper` archives for Darwin amd64/arm64, Linux
  amd64, and Windows amd64.
- SHA-256 checksums for every release archive.
- The same schema-1 NDJSON operations: `hello`, `acquire`, `release`, and
  `shutdown`.
- Additive `hello` fields describing the provider and whether elevation is
  required.

## Storage safety

The Unix providers reject unsupported CoW rather than degrading to a physical
copy. Before deleting a Child, Release verifies the lease ID, a random 256-bit
ownership token, an exclusive `.testplay-storage-owner` marker, and the Child
root device/inode identity. It then performs a no-replace rename into a
same-filesystem quarantine path and revalidates the object before recursive
deletion.

This narrows path-replacement races; it does not claim to eliminate every
adversarial filesystem TOCTOU race around the final recursive deletion. An
existing empty Mount directory is recreated with its recorded permission bits,
without claiming restoration of the original directory object or all metadata.

Linux clone failures are classified conservatively: explicit reflink or
cross-device unavailability reports `cow-unavailable`; cancellation reports
`cancelled`; permission, disk-full, I/O, source-read, and unknown `cp` failures
report `child-create-failed`.

## Validation boundary

```text
Windows VHDX lifecycle: PROVEN
Windows Unity compatibility: PROVEN within recorded scope
GNF_ single-worker: COMPATIBLE / BENEFICIAL

macOS APFS helper: VALIDATED in one recorded arm64 APFS environment
Linux reflink helper: IMPLEMENTED / NATIVE HARDWARE NOT YET

Forced-termination recovery: NOT YET
Parallel workers: NOT YET
Unix Unity compatibility: NOT YET
Production Storage Backend integration: NOT YET
Production readiness: NOT YET
```

Skipped hardware validations are not counted as passes. No Windows VHDX,
Linux-native reflink, or Unix Unity Library hardware run was repeated as part of
release packaging.

## Public compatibility

- Public `testplay` commands, request fields, JSON schema, and exit-code
  contract are unchanged.
- Storage Helper `schemaVersion` remains `1`; implementation version is `v2`.
- The Windows provider remains `vhdx-differencing`; macOS reports
  `apfs-clonefile`; Linux reports `linux-reflink`.
- No released default-provider or automatic backend-selection behavior changed.

## Known limitations

- The helper is an experimental integration primitive, not a public CLI
  backend.
- Forced-termination recovery is not implemented.
- Parallel-worker storage orchestration is not implemented.
- macOS/Linux Unity Library compatibility has not been validated.
- Linux native reflink hardware validation has not been run.
- The legacy package name `internal/vhdxstorage` remains; a future rename to
  `internal/cowstorage` or `internal/workspacestorage` is deferred.
