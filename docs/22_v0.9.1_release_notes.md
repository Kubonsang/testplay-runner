# TestPlay Runner v0.9.1 — Release Notes

**Release date:** 2026-06-05
**Previous release:** v0.9.0

---

## Summary

v0.9.1 is a scenario orchestration hotfix from real NGO multi-client
dogfooding. v0.9.0's IPC bus and failure correlation worked, but the
scenario workflow still had sharp edges: CLI filters were not forwarded
to scenario instances, dependency phase naming was confusing, and unknown
scenario fields could be silently ignored.

This release keeps the v0.9 IPC contract intact while making scenario
mode usable for focused multi-instance runs.

---

## What's Fixed

### 1. `--filter` and `--category` now apply to scenario instances

`testplay run --scenario scenario.json --filter MyTest --category NGO`
now forwards both selectors to every Unity instance in the scenario. This
prevents a focused multi-client check from accidentally running the full
test suite in each instance.

`--compare-run`, `--shadow`, `--reset-shadow`, and cache flags are also
forwarded through the same scenario request path.

### 2. `depends_on_phase` is now a supported scenario field

Scenario files can specify the phase a dependent instance requires from
its dependency:

```json
{
  "schema_version": "1",
  "instances": [
    {"role": "host", "config": "testplay.json", "ready_phase": "running"},
    {"role": "client", "config": "testplay.json", "depends_on": "host", "depends_on_phase": "running", "ready_timeout_ms": 120000}
  ]
}
```

If `depends_on_phase` is omitted, the dependency's `ready_phase` is used;
if both are omitted, the default remains `"compiling"`.

### 3. Scenario JSON now rejects unknown fields

Scenario parsing uses strict JSON decoding. Mistyped fields such as
`depends_on_phase_typo` now fail validation instead of being silently
ignored. Conflicting dependency phase requests are also rejected at load
time because the current ready signal is one channel per dependency role.

### 4. Dependency errors report the actual waited phase

Timeout and fast-fail messages now use the dependency phase requested by
the waiting instance. A client waiting for host `"running"` no longer
reports that it was waiting for `"compiling"`.

## Verification

```bash
go test ./...
```

The test suite covers strict scenario parsing, `depends_on_phase`
round-trip parsing, dependency timeout messaging, and scenario-level
filter/category forwarding to Unity CLI args.

---

## Upgrade Notes

Existing scenario files remain valid unless they contain unknown fields.
If a previous workaround added an unsupported field, v0.9.1 will now
return exit 5 with a validation error. Replace those fields with the
supported `depends_on_phase` and increase `ready_timeout_ms` for large
Unity projects that need more than the 30s default.
