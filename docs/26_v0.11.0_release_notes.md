# TestPlay Runner v0.11.0 — Release Notes

**Release date:** 2026-07-14
**Previous release:** v0.10.0

---

## Summary

v0.11.0 — “The Honest Contract Hardening” — removes the failure modes that are
most expensive for an AI agent: a command that looks green without running a
test, a timeout mislabeled as a compile error, a partial test list presented as
complete, a foreign Unity run captured as testplay's result, or an ambiguous
warm run silently executed a second time through the cold fallback.

The guiding rule is fail closed. When testplay cannot prove what happened, it
returns a structured non-success result instead of guessing.

## Breaking upgrade: CLI and Unity package move together

The warm bridge wire protocol is now **protocol 2**. It binds every request to
one Editor session and one owned Unity Test Framework run GUID. The v0.11 CLI
must be paired with `com.testplay.bridge` 0.11.0; protocol-1 and protocol-2
packages are intentionally not treated as compatible.

Upgrade both components before running bridge tests. During a mismatch, the CLI
refuses the warm path before execution and may use the cold fallback.

## What changed

### 1. Exit-code honesty

- Cold-process deadline and signal cancellation now surface as exit 4 and exit
  8 instead of being swallowed by the killed process's exit status.
- A `--filter` or `--category` that selects zero tests returns **exit 10** with
  an actionable warning. An unfiltered test-less project remains exit 0 but is
  explicitly disclosed.
- Missing, non-executable, or otherwise unlaunchable Unity binaries return exit
  1 with `error` and `hint`, not an empty exit-2 compile result.
- Bare invocation, unknown flags/commands, hidden completion paths, stray
  positional arguments, and malformed configuration return one JSON error and
  exit 5. Help remains on stderr.

### 2. Strict configuration and honest test inventory

- `testplay.json` accepts exactly one JSON value, rejects unknown keys, and
  requires `schema_version: "1"`.
- Relative `project_path` is anchored to the config directory; relative
  `result_dir` is anchored to the resolved project.
- List cache schema 2 records whether the source run was a full inventory and
  which test platform produced it. Filtered runs no longer poison the cache,
  and old or partial cache entries are invalidated instead of trusted.
- `testplay list` uses static fallback only when configuration is genuinely
  absent; malformed configuration remains an exit-5 error.

### 3. Scenario isolation and regression baselines

- Each scenario instance may specify its own `compare_run`; a missing baseline
  yields `new_failures: null` plus a warning, never a false empty list.
- Instances resolving to the same Unity project are forced into isolated shadow
  workspaces. Identity uses filesystem evidence, including Windows case and
  junction aliases; uncertainty also chooses isolation.
- Dependency phases and negative ready timeouts are validated before launch.
- Scenario instance launch errors and hints are preserved, and aggregate exit
  precedence ensures exit 10 cannot hide exits 1–9.

### 4. Warm bridge protocol 2: owned execution

- Requests carry `bridge_session_id`; an old-session request is sealed rather
  than executed after Editor restart.
- Only callbacks for the run GUID returned by `TestRunnerApi.Execute` may finish
  a request. Human Test Runner runs cannot be captured as bridge output.
- `RunFinished` writes a private pending result. The bridge waits through Test
  Framework cleanup and two authoritative inactive observations before
  publishing the terminal response and reporting idle.
- Cancellation, synchronous launch errors, callback errors, and domain reload
  recover through durable state instead of wedging the bridge.

### 5. No-replay terminal rule

Durable markers distinguish `not_started` from `possibly_started`.

- Only `not_started` may fall back to a cold run.
- `possibly_started` returns exit 9 and is never automatically rerun.
- A completed response with missing or invalid result XML, a terminal publish
  failure, or unrecoverable domain-reload ambiguity follows the same rule.
- Exactly one terminal `done`/`run_finished` event is written.

This can produce an explicit unknown result even when tests may have passed.
That trade-off is intentional: an unknown is safer than duplicated side effects
or a result owned by the wrong run.

### 6. CI and release hardening

- OS matrix jobs no longer cancel one another on the first failure.
- Ubuntu and Windows keep the Go 1.22.12 compatibility floor.
- macOS and release builds use Go 1.26.4, producing the Mach-O `LC_UUID`
  required by macOS 26.
- A manual Release Preflight builds all five archives, verifies checksums,
  executes Linux and macOS ARM candidates, and inspects both Darwin binaries for
  exactly one `LC_UUID` before the immutable tag is created.

## Upgrade checklist

1. Download the v0.11.0 CLI for the target OS.
2. Install `unity/com.testplay.bridge` from the same v0.11.0 tag.
3. Wait for Unity package import and a protocol-2 idle handshake.
4. Run `testplay version` and a narrow EditMode filter before the full suite.
5. Refresh any schema-1 list cache with an unfiltered run.

Strict configuration may reveal keys that older versions silently ignored.
Fix those keys rather than deleting validation.

## Scope

- Warm bridge: EditMode only.
- Two-phase configurations and scenario mode remain cold.
- PlayMode-warm, scenario/network warm orchestration, and documented hard abort
  of a hung Unity Test Framework run remain deferred.
- The protocol-2 warm bridge requires Unity 6 (6000.3+) and was revalidated on
  Unity 6000.3.10f1 on Windows. It depends on per-run GUID activity and
  cancellation APIs absent from Unity 2022.3, so v0.11 does not claim a
  protocol-2 warm path on that LTS editor.
