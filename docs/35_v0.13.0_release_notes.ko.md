# testplay v0.13.0 릴리스 노트

`v0.13.0`은 7일 관찰을 마친 `v0.13.0-rc.1` 계보를 native-tested
Differencing VHDX provider 변경 없이 승격합니다. `vhdx-diff`는 Windows 11
x64의 명시적 experimental opt-in이며 direct-batch와 legacy-shadow 선택은
계속 기본값입니다.

## Differencing VHDX workspace

- compatibility key마다 immutable dynamic NTFS parent VHDX 하나를
  commit하고, 실행마다 private writable child를 격리 workspace의
  `Library`에 mount합니다.
- 관리자가 `testplay storage install`을 한 번 실행해 한 Windows 사용자
  SID용 LocalSystem broker를 설치합니다. 이후 CLI와 AI agent는 인증된
  local named pipe를 비관리자 권한으로 사용합니다.
- 명시적 `vhdx-diff`는 fallback하지 않습니다. 명시적 `auto`는
  parent/child 작업 전 broker 연결 또는 capacity admission이 실패할 때만
  `legacy`를 선택할 수 있습니다. 둘 다 암묵적으로 선택되지 않습니다.
- 기본 allocated-byte quota는 32 GiB, host-free floor는 20 GiB, 신규 child
  reserve는 2 GiB입니다.
- physical partition을 format하거나 ReFS, Dev Drive, Defender, registry
  설정을 변경하지 않습니다.

## 검증 계보

Provider logic은 `beabf36a299572607232806807ad9b9c2d4cb222`에서 계속
동결되어 있습니다. fixture/GNF_ 1·2·4 worker, 강제 종료, broker restart,
Windows reboot, quota/LRU, retained workspace native gate가 통과했습니다.
공개 RC는 한 대의 Windows 11 x64 NTFS host에서 blocking issue 없이 Day
0/3/7 관찰을 완료했습니다. immutable artifact hash는
[`docs/32_v0.13.0-rc.1_validation.md`](32_v0.13.0-rc.1_validation.md)와
[`docs/33_v0.13.0_rc_observation.md`](33_v0.13.0_rc_observation.md)에 있습니다.

정식 Windows `testplay.exe`와 `testplay-storage-helper.exe`에는 공개 신뢰
Authenticode 서명과 RFC 3161 timestamp가 유효해야 합니다. workflow는
서명 후에만 checksum과 GitHub provenance를 만듭니다. 관리자 broker 설치
전 세 항목을 모두 검증하십시오. 유효한 서명이 있어도 SmartScreen 평판이
즉시 형성된다고 보장하지 않습니다.

## 명시적 한계

- GNF_ four-worker 준비 시간은 worker당 14.794–15.122초로 별도 10초
  목표를 넘었습니다.
- GNF_ 8 worker, 장시간 child 성장, 다중 hardware 호환성은 미측정입니다.
- 일반화된 성능 우위, 자동 기본 승격, production readiness를 주장하지
  않습니다.
