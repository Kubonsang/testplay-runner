# TestPlay Runner v0.12.0 — Native CoW Storage Foundation

릴리스 날짜: 2026-08-03.

## 요약

v0.12.0은 크로스 플랫폼 `testplay-storage-helper`를 실험적 통합 primitive로
배포합니다. 공개 `testplay` CLI 계약은 그대로이고 Storage Helper protocol은
schema 1을 유지하며 Helper 구현 버전은 `v2`를 보고합니다.

| 플랫폼 | 네이티브 Provider | Helper 배포 대상 |
|---|---|---|
| Windows | Differencing VHDX | `windows-amd64` |
| macOS | APFS `clonefileat(2)` | `darwin-amd64`, `darwin-arm64` |
| Linux | GNU `cp --reflink=always` 기반 reflink | `linux-amd64` |

Production 기본 backend는 바뀌지 않습니다. Helper는 `testplay run`에 연결되지
않고 자동 선택되지 않으며 물리 복사로 조용히 폴백하지 않고 아직
production-ready가 아닙니다.

## 포함 항목

- 기존 `testplay` CLI 아카이브: Darwin amd64/arm64, Linux amd64/arm64,
  Windows amd64.
- Darwin amd64/arm64, Linux amd64, Windows amd64용 별도
  `testplay-storage-helper` 아카이브.
- 모든 릴리스 아카이브의 SHA-256 checksum.
- 동일한 schema-1 NDJSON 명령: `hello`, `acquire`, `release`, `shutdown`.
- Provider와 elevation 필요 여부를 알리는 additive `hello` 필드.

## Storage 안전성

Unix Provider는 CoW 미지원 시 물리 복사로 저하하지 않고 실패합니다. Release는
Child를 삭제하기 전에 Lease ID, 무작위 256-bit ownership token, 독점 생성된
`.testplay-storage-owner` marker, Child root device/inode를 검증합니다. 이후 같은
filesystem의 quarantine 경로로 덮어쓰기 없는 rename을 수행하고 객체를 다시
검증한 뒤에만 재귀 삭제합니다.

이 절차는 경로 교체 경쟁을 줄이지만 마지막 재귀 삭제를 둘러싼 모든 적대적
filesystem TOCTOU 경쟁을 제거한다고 주장하지 않습니다. 기존 빈 Mount
디렉터리는 기록된 permission bit로 다시 생성하며, 원래 디렉터리 객체나 모든
metadata를 복원한다고 주장하지 않습니다.

Linux clone 실패는 보수적으로 분류합니다. 명시적 reflink 미지원과 cross-device
실패는 `cow-unavailable`, 취소는 `cancelled`, 권한·디스크 부족·I/O·원본 읽기 및
알 수 없는 `cp` 실패는 `child-create-failed`입니다.

## 검증 경계

```text
Windows VHDX lifecycle: PROVEN
Windows Unity compatibility: PROVEN within recorded scope
GNF_ single-worker: COMPATIBLE / BENEFICIAL

macOS APFS helper: VALIDATED in one recorded arm64 APFS environment
Linux reflink helper: IMPLEMENTED / NATIVE HARDWARE NOT YET

Forced-termination recovery: NOT YET
Parallel workers: NOT YET
Unix Unity compatibility: NOT YET
Production Storage Backend integration: NOT YET
Production readiness: NOT YET
```

실행하지 않은 Hardware 검증은 PASS로 세지 않습니다. 릴리스 패키징 과정에서
Windows VHDX, Linux native reflink, Unix Unity Library Hardware 검증을 다시
실행하지 않았습니다.

## 공개 호환성

- 공개 `testplay` 명령, request field, JSON schema, exit-code 계약은 그대로입니다.
- Storage Helper `schemaVersion`은 `1`, 구현 버전은 `v2`입니다.
- Windows Provider는 `vhdx-differencing`, macOS는 `apfs-clonefile`, Linux는
  `linux-reflink`를 보고합니다.
- 릴리스된 기본 Provider나 자동 backend 선택 동작은 바뀌지 않았습니다.

## 알려진 제한

- Helper는 실험적 통합 primitive이며 공개 CLI backend가 아닙니다.
- Forced-termination recovery는 구현되지 않았습니다.
- 병렬 Worker Storage orchestration은 구현되지 않았습니다.
- macOS/Linux Unity Library 호환성은 검증되지 않았습니다.
- Linux native reflink Hardware 검증은 실행되지 않았습니다.
- 기존 package 이름 `internal/vhdxstorage`는 유지합니다.
  `internal/cowstorage` 또는 `internal/workspacestorage`로의 변경은 향후 과제입니다.
