# TestPlay Runner v0.9.2 — Release Notes

**Release date:** 2026-06-05
**Previous release:** v0.9.1

---

## Summary

v0.9.2 improves diagnostic reliability for shadow two-phase runs. GNF_
dogfooding showed a case where Unity's compile invocation returned a
non-zero exit code even though no C# compile errors were present and the
backend build log had already reported success. The old fallback reported
this as exit 2, which incorrectly suggested a source compile failure.

This release makes the contract sharper: exit 2 is reserved for confirmed
C# compile errors, while compile invocation failures without C# errors are
reported as exit 6 with a message that points at Unity/editor logs,
package import, shadow cold import, license, or build-target setup.

---

## What's Fixed

### 1. Non-zero compile invocation without C# errors is exit 6

In two-phase mode, the compile-only Unity invocation can fail before the
test phase for reasons outside project source code. v0.9.2 now classifies
that path as a build / Unity invocation failure:

```json
{
  "exit_code": 6,
  "errors": [
    {
      "message": "Unity compile invocation exited with code -1 (no C# compile errors in stderr); check Unity/editor logs, package import, shadow workspace cold import, license, or build-target setup"
    }
  ]
}
```

### 2. Confirmed C# compile errors still return exit 2

The C# compiler error parser still takes precedence. Lines such as
`Assets/Foo.cs(12,3): error CS0246: ...` continue to produce exit 2 with
file, line, column, and absolute path details.

### 3. Compile phase timeouts are unchanged

If the compile phase deadline itself fires, the result is still exit 4
with `timeout_type: "compile"`. This keeps phase timeout handling
separate from non-zero Unity invocation exits.

---

## Upgrade Notes

Agents should no longer treat every compile-phase non-zero exit as a
source edit request. Use this split:

- Exit 2 with populated C# compile errors: fix source.
- Exit 4 with `timeout_type: "compile"`: increase/warm the phase budget.
- Exit 6 with no C# compile errors: inspect Unity environment, package
  import, shadow cold import, license, or build-target setup.

For large projects using `--shadow`, the first cold workspace import can
look expensive enough to hit compile-phase budgets or fail before tests
start. Warm the shadow cache or compare with a non-shadow run before
attributing the failure to test code.
