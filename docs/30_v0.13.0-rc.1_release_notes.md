# testplay v0.13.0-rc.1 release notes

`v0.13.0-rc.1` makes the native-tested Differencing VHDX workspace provider
available as an explicit experimental opt-in on Windows 11 x64. Existing
direct-batch and legacy-shadow selection remains the default.

## Differencing VHDX workspaces

- One immutable 64 GiB dynamic NTFS parent VHDX is committed per compatibility
  key; each run receives a private writable differencing child.
- The child volume is directory-mounted at the isolated workspace's `Library`.
  `Assets`, `Packages`, and `ProjectSettings` remain physical workspace copies.
- `testplay storage install` performs a one-time elevated install for one user
  SID. The LocalSystem broker then serves ordinary non-elevated CLI and AI-agent
  requests over an authenticated named pipe.
- Explicit `vhdx-diff` never falls back. Explicit `auto` may use `legacy` only
  when broker connection or capacity admission fails before parent/child work
  starts. Neither is selected when the user does not request it.
- `--keep-workspace`, `workspace attach/remove`, allocated-byte quota, host-free
  protection, protected-parent LRU, and ownership-safe restart/reboot recovery
  are included.

The default store quota is 32 GiB of host-allocated VHDX bytes, the host-free
floor is 20 GiB, and a newly admitted child reserves 2 GiB. The provider does
not format a physical partition or change ReFS, Dev Drive, Defender, or
registry settings.

## Installation and integrity

Read the [Differencing VHDX quickstart](vhdx-diff-quickstart.md) before running
the elevated install. The RC Windows binary is not Authenticode-signed, so
Windows SmartScreen may warn. Verify both `checksums.txt` and its GitHub
provenance before approving execution:

```powershell
gh attestation verify `
  .\testplay_0.13.0-rc.1_windows_amd64.zip `
  -R Kubonsang/testplay-runner
```

The release workflow creates a draft prerelease first. The exact draft Windows
asset must pass the release-candidate native smoke before publication.

## Explicit limitations

- Full GNF_ workspace preparation measured 14.794–15.122 seconds per worker,
  above a separate 10-second objective. This does not fail the explicit opt-in.
- GNF_ 8 workers and long-running child growth are not measured.
- A remote named-pipe connection from a second physical machine is not measured;
  the pipe is configured to reject remote clients.
- Generalized performance superiority, automatic default promotion,
  production readiness, and release readiness are not claimed.
